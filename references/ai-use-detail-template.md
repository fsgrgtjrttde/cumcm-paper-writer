# AI 工具使用详情模板

仅在实际使用 AI 时创建 `AI工具使用详情.pdf`。内容必须与论文参考文献前的声明一致，并由参赛队逐项核实。不要记录姓名、学校、赛区、队号、账号、密钥或其他身份信息。

## 首页信息

- 文件标题：AI 工具使用详情
- 对应论文题号：只写 A/B/C/D/E 等题号，不写队号
- 使用结论：概括实际用途类别
- 人工责任说明：核心建模与分析由参赛队主导，AI 输出均经人工审查和核实

## 工具记录表

每个工具、模型版本和用途环节单列一行；同一工具承担显著不同任务时分行。

| 序号 | 工具名称 | 版本或模型 | 使用日期/阶段 | 具体目的和环节 | 主要提示方式与使用过程 | 采纳内容 | 人工修改 | 核验方法与证据 | 结论 |
|---|---|---|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  |  |  |  |

- “具体目的和环节”定位到题意理解、资料检索、代码调试、结果核对、语言润色或排版。
- “主要提示方式与使用过程”概括输入材料、约束、关键追问和迭代，不粘贴身份数据或密钥。
- “采纳内容”区分直接采纳、修改后采纳和未采纳。
- “人工修改”说明实质修正；仅语言润色时可简述。
- “核验方法与证据”写代码复跑、手算、独立算法、原始文献、官方页面、测试集或图表编号，不能只写“已核验”。
- “结论”填通过、部分通过或未采用，并与论文一致。

## 生成与验证流程

1. 使用 DOCX Skill 生成详情 DOCX，设置表头跨页重复和长文本换行。
2. 导出 PDF，文件名严格为 `AI工具使用详情.pdf`。
3. 使用 PDF Skill 提取全文，核对工具名称、版本/模型、目的与环节、提示过程、采纳/修改/核验信息。
4. 使用 PDF Skill 逐页渲染，检查中文字体、表格裁切/丢行、页码、空白页和身份信息。
5. 放入支撑材料后，重新检查压缩包内文件名和论文声明一致。

任何字段仍为空、含 `【简要用途】` 等占位符、或无法说明人工核验依据时，不得交付。
