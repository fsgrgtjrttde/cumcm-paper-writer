# 论文证据工作流

本文件用于写作前的内部规划，也可作为向用户索要材料的清单。不要把未完成的内部台账直接放进参赛论文。

## 证据台账字段

为每个子问题记录：

| 字段 | 内容 |
|---|---|
| 主张 ID | `q1-c1`、`q2-c2` 等稳定编号 |
| 核心主张 | 一句可被证伪的结论 |
| 公式/假设 | 公式编号、变量、约束和假设依据 |
| 结果证据 | 结果文件、表名/行列、图文件或代码函数 |
| 验证证据 | 对照、误差、敏感性、残差或外部文献 |
| 正文位置 | 章节、小节、图表编号 |
| 摘要候选 | 是/否；若是，记录最终数值和单位 |
| 引用键/来源 | `citation_key`、原始出版页/DOI、`引用核验台账.tsv` 行号 |
| 状态 | `缺失`、`待核验`、`可写`、`已复核` |

没有 `可写` 或 `已复核` 状态的主张不得进入摘要和结论。

## 证据闭环

每个子问题至少闭合以下链条：

```text
题目要求 -> 变量/假设 -> 模型方程 -> 可运行代码 -> 真实输出
       -> 图表/数值 -> 验证或误差 -> 正文主张 -> 摘要结论
```

链条中任何一环缺失都要回退，而不是用“预计”“理论上”补齐结果。

## 摘要数值回溯

摘要中的每个数值建立以下映射：

```text
摘要句 -> 正文小节 -> 表/图/公式 -> 输出文件 -> 复现命令 -> 输入数据哈希
```

四舍五入只能发生在最后一步，并在全文保持一致。百分比必须记录基准分母；误差必须记录误差定义和评价集。

## 章节大纲冻结

长篇正文前先冻结：

1. 每个子问题的一个主模型和必要的辅助模型；
2. 每个主张的图、表、公式和代码路径；
3. 结果和结论的单位、有效数字和引用；
4. 失败、边界和敏感性分析；
5. 参考文献与正文引用的双向编号。

正文、数据、图表或规则发生实质变化后，重新核对受影响映射。

## 交付前抽检

- 随机抽取 3 个摘要数值，回到代码输出核对。
- 随机抽取每个子问题至少 1 个图/表，确认正文有解释和引用。
- 检查所有公式中的变量是否在符号表或首次使用处定义。
- 检查所有外部事实和方法是否有正文引用和文末条目。
- 检查附件、代码、图表和支撑材料文件名是否与附录列表一致。
- 抽查每个正文引用：正文键、`.bib`/`\\bibitem` 条目和引用核验台账必须一一对应；引用核验器必须返回 `RESULT=PASS`。
